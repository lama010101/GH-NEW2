- **MP-FIX-DO-AUTH-REDIRECT-001** (2026-06-27): **RESOLVED PartyKit DO server-to-server fetch redirected to /login (root cause of lobby stuck on "Loading session...").** The PartyKit Durable Object's internal `fetch()` calls back into the Next.js app — cold-start `GET /api/compete/[gameId]` (loadFromDB) and `POST /api/compete/[gameId]/join` (JOIN_ROOM handler) — carry an `x-partykit-secret` header but no browser session cookie. The auth middleware in `src/middleware.ts` did not recognize that header, so it redirected these requests to `/login` and returned the login page HTML. The DO then failed JSON parsing (`Unexpected token '<', "<!DOCTYPE "... is not valid JSON`), never called `applySnapshotAndBroadcast` with valid data, and no usable `STATE_UPDATE` reached the client — `snapshot` stayed null forever. Fix: added a single check in `middleware()` — if the request carries `x-partykit-secret` matching `process.env.PARTYKIT_SECRET`, skip the `/login` redirect and let the request reach the route handler.
